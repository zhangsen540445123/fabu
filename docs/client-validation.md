# 蚁小二接入验证记录

日期：2026-11-06。仅记录脱敏事实，不包含账户数据、网页原文、媒体或令牌。

## 已实现并通过离线测试
- 使用 Windows ShellExecuteEx 打开配置的真实 `.lnk`，保留工作目录与参数。
- 精确目标路径匹配进程，刷新窗口所有者后才能恢复，不根据进程名称猜目标。
- 90秒总预算、最多两次启动、仅确定无进程时重试；后台/隐藏窗口不重复启动。
- 只读 UIA 探查使用独立自有子进程限时；超时只结束本程序的探查子进程。
- 页面必须来自可信内嵌文档并有内容控件；窗口标题和外壳不证明就绪。
- 不读取登录凭证，不处理现有任务。诊断不保存原始控件数据。
- 语义选择器唯一性、平台+稳定账号身份、提交记录关联、UNKNOWN不重试、安全桌面守卫。
- 单客户端控制命名互斥锁；冲突不释放他人锁。

## 实机结果
- 快捷方式解析成功，目标程序存在，工作目录与目标目录一致，无额外启动参数。
- 可以检测6个客户端进程和一个主窗口。
- 正式 `client start --timeout 15` 能走窗口检测与恢复流程，但最终返回 `ui_unavailable`。
- 原生 pywinauto 只读探查返回外壳25个可用控件，只有file来源的外层文档；没有可信web文档或账号页标签。
- 独立电脑工具同样只读到外层文档，截图可见账号页，但图片不是可用于无人值守的语义控件证据。
- 进一步只读检查子窗口：Chrome_RenderWidgetHostHWND中的内嵌HTTPS文档确实存在，但UIA把它及子控件标为IsOffscreen=true；实际可见的D3D窗口只暴露disabled空Pane。
- 因此不能通过忽略可见性、强制选隐藏控件来假定可安全操作；需要客户端受支持的可访问性行为验证。
- 过去通过真实快捷方式冷启动成功、曾读到已登录首页；不能据此推断当前发布页稳定可访问。

## 后续调查方向
先验证客户端是否能通过受支持的可访问性机制稳定暴露嵌入页面，不能将固定坐标/OCR当作通过。
如果需要客户端重启或改变启动参数，先确认没有待处理的人工作业；不强杀、不改用户快捷方式。
控件可访问后再只读核验账号稳定标识及投稿记录结构；未经批准不执行真实投稿。
如当前版本确实无法满足UIA门槛，应重新讨论发布接入方式；不擅自改用CLI或私有接口。

## 独立审阅修复
- 文档URL读取使用pywinauto实际支持的ValuePattern/legacy_properties，输入框内容不采集。
- 快捷方式配置变化立即停止，不能作为普通Shell错误进入其他启动路线。
- 未限时的Explorer/UIA fallback已禁用；Shell失败安全暂停，不持有锁进入可能无限阻塞的provider。
- fallback属于计划中的后续未完成项，必须实现隔离/剩余截止时间/再次配置核验后才可启用。
- inspect尊重指定探查超时，subsecond启动预算使用有效poll间隔。
- 修复后离线测试77通过，静态检查通过；这些不能替代实机投稿接入验收。
