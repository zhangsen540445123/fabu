# CPU/GPU 混合处理：当前交付与验收

日期：2026-11-07。本轮是混合编码的软件接入与能力诊断，不代表本机已经获得GPU提速。

## 使用方式

在“处理流水线”编辑或新建预设，通过“处理加速”选择：

- **自动加速**：任务开始前检测NVENC；检测通过时采用CPU滤镜 + NVIDIA H.265编码，检测失败则以固定原因明确回退CPU。
- **CPU处理 + GPU编码（必须可用）**：检测失败暂停，不悄悄使用CPU。
- **CPU兼容模式**：保留现有libx265/fast/CRF配置。

既有预设默认维持原CPU语义，保存只生成新版本，不修改正在运行的任务或已完成输出。新建空白预设默认auto。GPU参数当前为独立的p5/HQ/VBR/CQ20候选配置，不声称等同CPU CRF20；本机画质与速度验收仍待驱动适配后完成。

界面可查看最近一次硬件检测及实际执行后端；任务分为来源准备、输入校验、硬件检测、编码、输出校验。新成片保存各阶段耗时。旧成片没有历史分阶段数据时，不编造耗时。

## 本机实测：驱动不兼容

- 设备：NVIDIA GeForce GTX1650，CPU Ryzen7 5800H。
- 初始3帧1440p合成测试在初始化即失败：当前FFmpeg要求NVENC API13.1，驱动提供12.0。编码器出现在列表中，不代表可以调用。
- 正式HardwareProbe再次得到`driver_incompatible`。原始驱动错误只保留在开发忽略目录，产品只返回固定安全原因，不转发外部错误全文。
- 没有更新驱动或FFmpeg，没有降低输出分辨率、绕过验证、调用收费/云服务。
- 真实GPU吞吐、画质与全GPU快速通道尚未通过本机验收。不能宣称快几倍或已启用GPU。

## 已实现的保护

1. 既有预设语义、处理计划及样片摘要保持兼容；当前历史1份计划、1份样片真实摘要复算通过。
2. 任务开始前冻结实际编码器、设备/驱动/工具指纹、质量参数及回退原因。重试沿用冻结选择，不在中途换后端。
3. GPU测试包含固定6帧1440p30合成编码、文件大小、HEVC/像素格式/帧数/时长检查和解码检查；仅列出编码器不会放行。
4. 能力缓存绑定工具与设备环境，成功15分钟、失败1分钟；每次使用前重新获取环境身份。跨进程证据仅供显示，不能作为GPU授权缓存。
5. GET硬件状态不启动编码或执行新的显卡查询；串行worker在新任务需要时运行探测。
6. 取消、超时、部分输出、错误帧率/时长不产生健康能力结论。异常有理数字段（包括0/0）归为probe_failed：auto回退，强制GPU暂停。
7. CPU和NVENC使用不同参数构建器；NVENC命令没有CRF或x265专属参数。
8. 本地输出无需样片审批；发布专属审批仍绑定实际编码后端，CPU样片审批不能错误用于GPU计划。
9. 输入/输出完整验证继续保留，包括整段帧几何/数量和视频、音轨解码。只增加阶段计时，没有以抽检替代完整验证。
