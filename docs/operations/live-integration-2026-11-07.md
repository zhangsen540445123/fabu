## 已定位并修复的代码问题
官方公开源码的发布入口及安装二进制的环回网关测试均显示，成功结果可能只有：

```json
{"ok":true,"action":"publish","version":"3.2.32","data":{"taskSetId":"loopback-synthetic-task","response":"loopback-synthetic-task"}}
```

旧Fabu要求`data.publishChannel`和`data.clientId`，把该标准成功回执判成`channel_mismatch`。

修复后：
- 合法成功包只记为`PROVIDER_ACCEPTED`，保留任务集ID；没有通道回显时`actual_channel=null`，绝不凭请求参数伪造平台通道证据。
- 明示错误通道、错误客户端、未知action/version/返回结构仍为UNKNOWN；也检查CLI归一化后`data.response`中的嵌套矛盾，未知嵌套形状不猜测。
- 不将接收当作SUBMITTED/PUBLISHED，不解锁费用/能力门禁，不允许重复投稿。
- 通过官方安装二进制向环回合成网关提交，证明真实CLI返回形状；该测试没有真实API Key、账号或外部请求，不是用户账号发布。
