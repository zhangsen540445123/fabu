# 安全与恢复检查记录

## 已验证的保护范围

- HTTP仅绑定127.0.0.1；Host、Origin、Sec-Fetch-Site检查，单次引导令牌、HttpOnly/SameSite会话和CSRF校验共同保护写接口。
- 跨站请求不能导入本地素材、保存连接、上传或提交发布；在URL里附加`live=true`或`approved=true`不会获得权限。
- 素材预览按不透明ID检索，路径必须留在管理目录。即使数据库媒体条目被替换成凭证文件路径，也不能经媒体接口读取。
- API Key和本地客户端ID使用Windows当前用户DPAPI保存；临时CLI配置仅允许当前用户及SYSTEM，调用结束清理。API不返回密钥，上传临时URL不进入状态接口和事件日志。
- FFmpeg/CLI不经shell拼接调用；参数为字面量数组，进程使用Windows Job Object归属管理。取消只涉及Fabu启动的工具，不按进程名终止用户程序。
- 源视频和源素材只读保留；不更改系统电源计划，不自动重启、唤醒或关机。
- 所有真实写接口仍未解锁。模拟Publisher没有网络传输；测试使用合成凭证、合成资源和合成账号，不能替代实际平台验收。

## 本次集成故障注入

1. 跨站/缺CSRF导入与发布：返回403，素材数量和投稿记录不增加。
2. 媒体ID数据库条目被改为凭证路径：返回404，不泄露文件内容。
3. 提供方异常文本含合成API Key与签名上传URL：状态只保留UNKNOWN；数据库导出与日志不含原始敏感文本。
4. 上传之后、本地保存回执时磁盘不足：投稿调用为0；重启上传记录为UNKNOWN。修复了该情形下界面曾允许再次排队的问题，现在HTTP拒绝提交，界面提示先核对临时存储/扣次。
5. 提交等待期间关闭Worker：取消信号使结果保守落为UNKNOWN；重启后不自动投稿，仅允许查询已有记录；其余平台仍为PENDING。
6. 同一来源/账号被其他任务占用时，预检状态直接提示来源冲突，不会再提供提交排队按钮。
7. 浏览器刷新后UNKNOWN保持，只显示对账，不显示重投按钮。Python实测Worker重启，浏览器实测刷新与对账，两者分别覆盖相应边界。

## 异常处理约定

- 不能把超时、断网或本地写库失败当作“没有发出”。可能有外部副作用时保留上传/投稿尝试，不盲目重试。
- 仅可靠证明“未提交”的目标可在新有限许可下继续；已提交目标跳过。
- 对账失败不抹去此前已确认的平台记录；平台后来拒绝预约则保存FAILED，但不会赋予“从未提交”的重试权限。
- 第一笔可能的真实投稿前冻结共享内容。恢复旧任务不能覆盖用户已经取消的状态，也不能修改新的内容版本。
- 成功编码但尚未验证的文件不提升为成片，不能进入发布。
- `resource_blocked`与平台UNKNOWN不同：上传资源结果不明时不能重新排队投稿或盲目上传，先人工/可信适配器核对资源与额度。

## 威胁模型与未解决项

- 这是单用户Windows本地工具，不是多租户网站。DPAPI防止其他Windows用户直接解密，但不抵抗已经控制当前用户会话/进程的恶意程序。
- 防路径逃逸检查不能替代操作系统级隔离；不建议与不可信本机进程共享可写的数据/工具目录。
- Evidence登记仅面向可信操作员/适配器，没有Web登记入口。签名和类型检查不能使虚构的“官方证据”变为真实事实。
- 蚁小二免费扣次、临时存储有效期/容量、HEVC接受、实际平台回执格式及平台独立预约尚未实测，仍需具体授权和原始证据。
- 指定YouTube链接的登录校验未解决，不读取浏览器cookies或规避权限。
- Windows启动/退出交付及独立全分支代码审阅仍需后续完成；本记录不是最终产品完整验收声明。

## 仓库敏感信息检查
本次对149个已跟踪文件进行了不输出匹配值的启发式扫描，仅在3个既有测试文件中命中合成Key字面量，未发现私钥/JWT字面量；新集成测试也只使用合成密钥。此扫描不能证明不存在所有形式的敏感信息，仍需独立整体审阅。
