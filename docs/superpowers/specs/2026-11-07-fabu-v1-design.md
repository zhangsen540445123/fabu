# Fabu v1：本地视频处理与三平台发布设计

日期：2026-11-07（Asia/Shanghai）
状态：**待用户整体验收，不代表获准编写产品代码、上传、投稿或预约发布。**

## 1. 目的与设计状态

帮助一位 Windows 用户每天处理约一条已获授权的 YouTube 视频：输入单条链接、中文标题和发布方式后，自动下载、制作适配原画面比例的成片、获取原封面、生成三平台表单，并通过蚁小二完成立即投稿或平台原生定时投稿。正常任务不需手工操作 IDM、剪映或蚁小二界面。

本文区分：
- **用户已确认**：对话中明确表达或已验收的要求。
- **工程建议，随本文待审批**：为避免继续逐项追问而提出的默认实现；不能说用户早已选择。
- **实机验证门槛**：依赖第三方的能力，设计批准不能替代技术验证或发布授权。

旧版 2026-11-06 设计中的“禁止 CLI/API”“无定时”“客户端 UI 自动化为唯一路线”等内容不再作为本轮新设计的依据。本文件经用户批准后才成为新版实施依据。仓库已有代码和旧文档处于未提交删除状态：本轮不恢复、不重写、不提交那些删除。

## 2. 已确认需求

1. 不增加付费 API、订阅、云服务器或运行时大模型费用；遇到付费要求停止，不代购。
2. 原视频已获授权；用户希望默认原创，具体声明必须依据平台真实语义映射，不能把授权转载直接等同于“自行拍摄”、独家或首发。
3. 三个目标：抖音“ASMR”、头条号“ASMR”、哔哩哔哩“枕畔慢时光”。昵称仅供显示；机器绑定使用平台与稳定账号 ID，ID 不写入设计或代码仓库。
4. 三平台使用同一成片、发布标题、YouTube 原封面和话题选组规则；B 站分类“生活经验”。
5. 根据用户填写的发布标题选组，不根据 YouTube 英文标题选组。
6. 同时支持立即发布与**平台原生定时**；三平台默认同一北京时间。定时是提前提交给平台，而非到时由本机启动上传。
7. 不再操作剪映；使用 FFmpeg 后台处理。用户已观看并认可 CRF20 的 15 秒对比样片。
8. 自动识别横竖屏和实际显示比例；不拉伸、不裁切、不额外补边，保留原片已有黑边。
9. 后续增加视频处理逻辑，首版不默认开启截图中的所有开关。
10. 当前仍在设计与技术验证阶段；用户此前“先不发布”的限制继续有效。

## 3. 选型比较与决策依据

### 3.1 发布路线

- 官方 CLI + 现有蚁小二本机客户端：当前优先候选。已获准安装、配置和只读查询，并成功读取三平台账号。尚未确认免费上传/投稿/平台预约的完整权限。
- 单独接入开放平台 API：收费接入不符合约束；没有证据证明能解决 CLI 限制前，不重复实现。
- 桌面界面自动化或分别控制各平台网页：备用评估方向，不属于本次默认实现。已有客户端控件读取不稳定记录；不得在 CLI 验证失败时暗中改用此路线。

**决定**：以 CLI 本机通道做有条件接入，完成第 11 节门槛前真实发布功能保持禁用。若不满足零新增费用或不能确认平台原生预约，则报告失败和证据，回到用户重新选路线；不把半自动产品当完整完成。

### 3.2 视频处理

- 继续控制剪映：保留熟悉效果，但依赖 GUI 状态；未选。
- FFmpeg 按明确参数处理：用户已选择，且已有样片验收。

### 3.3 产品与技术栈（工程建议，待本文批准）

- Windows 单用户本地网页 + 独立后台 Worker，不做公网网站或多用户 SaaS。
- Python 3.12、FastAPI/Pydantic、SQLite；前端 React/TypeScript/Vite，同源部署。
- 后台通过参数数组调用固定版本工具，禁止把标题、URL 拼进 shell 命令。
- yt-dlp 作为下载候选；FFmpeg/ffprobe 负责媒体处理；yxer 负责有条件的发布接入。工具版本、路径和校验信息可追溯，更新需显式操作，不运行时自动升级。
- 一个 Worker、一个实际发布执行者；SQLite 持久化任务与阶段结果，避免重启后丢状态。首版不引入 Redis、容器或分布式服务。

## 4. 视频参数与比例规则

### 4.1 用户认可的样片基准

- MP4，HEVC Main / yuv420p，libx265，preset=fast，CRF=20，30fps，Lanczos 普通缩放。
- 样片为 SDR BT.709；音频 AAC 192kbps、44.1kHz 双声道；没有变速、变调、降噪、混音或音乐。
- 样片区间 03:00–03:15，共450视频帧；剪映参考34.03MB、FFmpeg CRF20为13.87MB，约小59%。该比例不外推为所有视频的保证。
- 样片CPU线程限制为x265 pools=6、frame-threads=2，约26.2秒完成15秒片段。这不是全片/GPU性能承诺。
- 证据位于 `D:\devtools\idm\video\Fabu-comparison-20261107\REPORT.md` 和其 `evidence` 子目录；只读输入的大小与SHA-256前后一致，样片完整解码检查通过。

### 4.2 尺寸计算

先选择实际主视频轨，结合 coded width/height、sample aspect ratio、display matrix/rotation 确定显示比例，处理一次旋转并消除重复旋转风险。转换为方形像素后计算目标范围：

| 显示方向或比例 | 目标范围 / 常见输出 |
|---|---|
| 横屏，宽大于高 | 等比内接2560×1440；16:9→2560×1440，4:3→1920×1440 |
| 竖屏，高大于宽 | 等比内接1440×2560；9:16→1440×2560，3:4→1440×1920 |
| 正方形 | 1440×1440 |
| 超宽/特殊比例 | 对应范围内等比缩放，不裁切/拉伸/新增边框 |

使用统一比例因子，宽高取编码可接受的偶数值，保留最大约一至两像素的舍入差异。需要放大则普通缩放；超过目标范围则缩小。异常或无法解释的旋转、坏轨道、动态改变几何尺寸时暂停，不猜测。

### 4.3 尚未经样片验证的输入（工程建议）

- HDR、10bit特殊色彩、非直角旋转、复杂多音轨先暂停为不支持输入；不得给HDR仅贴BT.709标签冒充色调映射。
- 单音轨：保留44.1/48kHz原采样率和单/双声道布局，编码AAC；双声道192kbps，单声道128kbps。不偷偷丢弃多声道/多语种音轨。无声音则暂停让用户确认是否允许静音发布。
- 统一30fps采用时间轴保持方式补/丢帧，不改变总播放速度；输入60fps会减帧，不声称保留原运动流畅度。优先选择源的30fps版本（若有同质量候选）。
- 首版始终生成独立成片，避免复杂的“原文件直接复用”判断；后续可增优化。
- 若某平台不接受HEVC，不默默改用H.264；单独生成兼容样片，经用户确认后扩展预设。

## 5. 下载、封面与输入边界（工程建议）

- 仅单个YouTube视频链接，识别watch、youtu.be、Shorts及视频ID；不自动遍历播放列表/频道，不做直播录制。
- 下载前取得可用格式；优先接近目标尺寸的真实源（常见16:9为1440p），不存在则降到最佳可用低清格式。更高分辨率的下载取舍由实施时格式选择策略确定并展示，不固定下载4K。
- 需要分离音视频时合并；不偷偷下载静音视频当完成。不自动读取浏览器cookies或复制登录态；需要认证时暂停并提供显式配置入口。
- 用户标题是发布标题，下载标题仅为来源信息。文件使用内部任务ID命名，杜绝路径穿越、非法文件名和标题导致命令注入。
- 封面自动读取对应YouTube视频原缩略图，优先最高可用尺寸，检查HTTP、图片格式、实际宽高并过滤低分辨率占位图；有问题再尝试其他尺寸。
- 不依赖第三方封面网页UI，不上传URL给不必要的第三方；用户示例 `L6imSiJLd9Q` 已读取到1280×720 JPEG，但尚未验证视频下载。
- 全部封面不可用就暂停；不自动换成视频截图。保留原封面，平台如要求另一比例，不擅自裁切，需要单独确认适配规则。
- 下载/处理失败可重试，但有上限、退避和原因；源链接或格式信息变化必须重新验证产物。

## 6. 发布模板

### 6.1 话题预设（用户已有分组，已通过界面只读核对）

| 组名 | 标签，按已观察顺序 | 标题匹配关键词 |
|---|---|---|
| 助眠 | 解压、助眠 | 无默认自动匹配；作为手动通用组 |
| 2aZjVP8u | ASMR、解压、助眠、剃光头 | 剃光头 |
| QKHLZMFO | 解压、助眠、ASMR、剪发 | 剪发 |
| WRHkkYwU | 解压、ASMR、剃须仙人、助眠 | 剃须仙人 |

### 6.2 各平台字段

共享成片、封面、标题、标签语义；每个平台根据其schema转成相应字段。B站标签数组不能原样当其他平台结构化挑战对象。

- 账号以平台+稳定ID绑定；昵称变化不改变绑定，同名不自动选第一项，账号失效暂停。
- B站“生活经验”从真实分类查询解析完整父子路径与ID，匹配失败/歧义暂停，不编造分类ID或raw对象。
- 原创是用户默认偏好。B站自制/转载、头条来源声明、抖音声明分开配置；授权事实不自动填“自行拍摄”。未完成语义核对的平台表单禁止提交。独家、首发、共创、活动报名、商品挂载不自动启用。
- 简介（工程建议）默认复用用户标题，不额外生成事实、署名或来源声明；用户可覆盖。超长标题/标签报错，不自动删改用户文字。
- 可见性（工程建议）为公开；无首评、不自动挂合集/地点/音乐。未知必填值只通过查询或用户确认获得。

## 7. 立即与平台原生定时

### 7.1 立即

素材和配置完成后按已授权的单任务流程提交，不默认插入人工确认一步；异常除外。研发阶段与尚未解锁真实写操作时不得实际提交。

### 7.2 原生定时

创建任务即开始准备，尽早上传并提交指定时间。时间输入/显示为Asia/Shanghai，内部存UTC时间点，向CLI使用其要求的毫秒时间戳。三目标共用同一时间，不能解释成本机定时启动上传。

1. 提交前对所有目标检查账号权限、支持的最早/最晚预约时间与必要字段，预留上传/处理余量；不能假设三个平台时间窗口一致。
2. 输入时间已过、太近或超范围时暂停，不自动改成立即发布/延期，不因为时间失效直接修改单平台时间。
3. 必须有证据证明真正的平台已接受指定账号、视频和时间的预约，而不是仅在蚁小二待执行队列中等待。
4. 只有完成上述验证后，才能宣称后续发布不依赖本机持续开机。客户端是否要常驻、何时可退出须以实测为准。
5. 已预约与已公开分开显示；审核、实际展示时延不能承诺绝对准点。后台关闭后状态显示最后核对时间，恢复后再同步，不能自动将过点等同于已公开。
6. 首版可修改/取消尚未提交的本地任务。已有任何平台预约/提交的任务不支持“一键改时”或远程删除；提示去对应平台处理，其他目标不随之重投。

## 8. 发布执行与防重复（工程建议）

### 8.1 资源与通道

通过官方CLI上传取得资源key，再构造payload；不假定本机通道绕开云端临时存储。默认不登记素材库；同一文件在权限、通道、有效期和API契约允许时复用资源对象，不强行声称只能上传一次。

始终显式使用本机通道和目标Client ID，校验、预览、提交参数一致。不得自动回退云通道。CLI私有接口、逆向cookie、固定坐标点击不属于首版。

### 8.2 持久化状态

任务级：NEW→INSPECTING→DOWNLOADING→PROCESSING→READY→PUBLISHING；另有PAUSED、FAILED、CANCELED。媒体就绪不是任务发布完成。

每目标独立状态：PENDING / PRECHECKED / SUBMITTING / PROVIDER_ACCEPTED / SUBMITTED / SCHEDULED / PUBLISHED / FAILED / UNKNOWN。聚合状态由三目标计算，可为部分完成。

- CLI进程成功/返回ok仅说明命令或中间任务成功，不能自动设PUBLISHED。
- SUBMITTED要求对应平台提交证据；SCHEDULED要求平台原生预约及目标时间证据；无法关联就UNKNOWN。
- 提交前持久化attempt ID、目标账号、payload摘要、素材标识、模式和目标时间，再开始有副作用的调用。
- 发生超时/崩溃，先根据返回任务ID和账号/素材/时间查记录；不能只凭同名标题判定成功。无法唯一匹配则保持UNKNOWN。
- UNKNOWN、PROVIDER_ACCEPTED和已提交状态不能自动重投，重启也不能直接变回PENDING。
- 明确未提交的临时错误可有限重试；成功目标跳过。没有证据的失败提示不能当成可安全重试。
- 相同账号+源视频ID+成片hash+元数据版本的未解决/已提交任务阻止重复创建；用户修改标题也不能绕过UNKNOWN的源视频级保护。
- 配置、标题、话题、处理参数、时间使用不可变任务快照。依据已确认的三平台同内容要求：在任何目标首次进入SUBMITTING前可创建新修订；首次可能产生平台副作用后，冻结该任务的共享视频、封面、标题、标签、声明与预约时间，禁止剩余目标改用另一版。即便首次提交结果为UNKNOWN也继续冻结。允许修复账号登录/网络后用同一快照恢复；修改共享内容必须走明确的新内容任务审核，不能绕过已有UNKNOWN保护。
- 三平台内部独立记录不等于强制三次收费提交。批量或分平台调用由公开契约和扣次证据决定；未确定前两种能力都视为未验证。

## 9. 运行、存储与凭证（工程建议）

- 程序页面只绑定127.0.0.1，不向局域网/公网开放。随机本地会话密钥、同源/Origin与CSRF保护，敏感接口不接受跨站调用。
- 窗口关闭不取消后台任务；本地阶段仍要求电脑运行。首版不修改系统电源计划，不强制唤醒，不承诺登录前无人值守。
- 媒体默认建议 `D:\FabuData\jobs`，数据库/设置建议 `%LOCALAPPDATA%\Fabu`；第一次启动展示实际路径与磁盘余量，用户可换目录。不迁移或覆盖现有媒体。
- 源视频、封面、成片默认保留，用户明确清理后才删；重试复用已验证文件。临时输出独立命名，完整校验后原子提升为正式成片。
- 空间预检结合源大小、成片保守估计和余量，长视频处理中持续检测；不足暂停，不自动删旧作品。
- 正式产品使用用户级Windows保护存储保存凭证；CLI需要明文配置时，仅在受限临时目录生成当前用户可访问的配置，用完清理。重启处理遗留临时文件，说明同用户恶意进程不在保护边界内。
- 当前验证凭证位于仓库外。禁止复制进文档/日志/截图/Git，不读取浏览器或客户端会话缓存。此前在聊天泄露的旧Key必须由用户撤销；不推测是否已撤销，不继续暴露。
- 不把名称“config”就当成无秘密对象；输出仅白名单字段，CLI错误正文可能含敏感数据，需脱敏。
- 之前发生工具环境与用户终端文件可见性不一致：最终安装验收必须在实际使用环境检查工具路径、配置与媒体可访问性；不能只用代理工具内成功替代用户端成功。

## 10. 扩展能力与明确不做的事项

处理接口接收源媒体+版本化预设，产出媒体清单，发布模块只消费已验证产物。预设将来可包含片头片尾、自有水印、布局、翻转、变速、透明叠加等明确操作。

首版不做可视化时间线、批量频道抓取、AI选片/超分、云端收费转码。所谓“微处理重编码”“画面去重”“MD5指纹注入”不是已定义算法，不默认加入，不承诺规避平台识别。预留步骤边界不等于提前搭建通用插件平台。

## 11. 实机能力门槛与阶段验收

### 已有证据

- yxer 3.2.32在用户PowerShell成功运行。
- API Key账号查询实际成功：三个明确账号均status=1；Client ID已配置并读回核对。
- YouTube示例原封面读取成功；个人话题组通过UI只读查看。
- FFmpeg CRF20片段解码验证通过，用户确认画面声音满足需求。
- 自动比例处理原则获认可；其他比例的实际样片尚未跑。

### 尚未验证，不得伪装完成
