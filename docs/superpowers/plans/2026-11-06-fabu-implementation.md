# Fabu Implementation Plan

> 实施方式：本会话逐任务执行，TDD；结尾独立审阅。第一阶段是必要可行性门槛。

**Goal:** 本地链接和标题到三平台可验证已提交。
**Architecture:** 独立本地网页/任务worker，下载、处理、发布模块隔离。
**Tech Stack:** Python3.12, FastAPI, SQLite/SQLAlchemy, React/TS, yt-dlp, FFmpeg, pywinauto。
**Spec:** ../specs/2026-11-06-fabu-design.md

## Global Constraints
- 不CLI/私有接口/坐标/运行时大模型，不处理用户现有任务。
- 不猜账号、必填枚举或原创声明；未提交证据不报成功。
- 冷启动自动完成；90秒就绪，最多两次且仅无进程重试。
- 第一阶段未通过不开始后续阶段，不生成假发布实现。

## Review Focus
- 能读到外层壳但不能读发布页时失败关闭。
- 同名非客户端窗口、不同安装路径进程、多个客户端窗口均不能误选。
- 系统锁定、人工操作、未知既存任务不能被覆盖。
- 名称/时间相同并不能构成唯一提交证据。
- 诊断不保存账户信息、令牌、网页原文到Git。

## Task 1: 蚁小二启动与只读接入验证
- [ ] 先测试Launcher状态机：冷启动、现有/托盘、90秒、仅无进程重试、登录/冲突/壳/锁定/多窗口。
- [ ] 实现平台无关模型和纯状态分类，Windows原生ShellExecuteEx边界与UIA探查。
- [ ] 先测试严格语义选择器、平台+身份匹配、提交证据规则、人工空闲守卫、互斥锁。
- [ ] 实现只读诊断CLI与可测试Windows适配器。诊断默认不操作窗口；--start显式启动。
- [ ] 保存脱敏实机观察并判断门槛，不能用截图识别取代稳定控件。
- [ ] 若启动/投稿/账号/记录任一未验证，则明确门槛未通过，不继续Task2。

## Task 2: 本地服务与账本（依赖Task1验收）
- [ ] 先测试创建幂等、SQL状态恢复、互斥、取消/修订/UNKNOWN屏障。

- [ ] 验证关网页不中断、重启恢复、绑定127.0.0.1和同源安全。

## Task 3: 下载（依赖Task2）
- [ ] 先测试URL、格式选择、音画合并、残缺文件与网络重试。
- [ ] 实现yt-dlp/EJS/Node/FFmpeg参数数组调用、进度、续传、代理配置。
- [ ] 授权源视频下载验证，信息/时长/轨道正确。

## Task 4: 视频处理（依赖Task3）

- [ ] 实机对比源/成片，确认比例/轨道/时长与质量。

## Task 5: 发布（依赖Task4与Task1控件证据）

- [ ] 经用户批准的授权测试视频在三平台实机测试。

## Task 6: 恢复与交付（依赖Task5）
